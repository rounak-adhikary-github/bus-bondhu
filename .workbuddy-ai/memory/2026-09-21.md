# 2026-09-21 — BusBondhu: duplicate stop merges + time display removal

## What was asked
Merge duplicate stop names across the dataset (Sec V / Salt Lake Sector V, Bekbagan /
Beck Bagan, Joka, "and all such names"), fix the routes those merges affect, and remove
the bus-time display unless real timings could be sourced.

## Timings decision
Researched WBTC's route list, the WB Transport Dept "Bus Time Table" page, Kolkata
Bus-O-Pedia and the community GTFS repo: **none publishes departure times or headways.**
So the time display was removed entirely rather than faked.
- `js/data.js` no longer emits `headway` / `first` / `last` / `est`.
- `js/app.js`: dropped `kolkataNow`, `fmtTime`, `resolveSelectedTime`, `buildTimeOptions`,
  `departuresInWindow`, `WINDOW_MIN`, `FREQ_THRESHOLD`, `STEP`, the `?at=` deep-link param.
  `computeRows()` now returns every connecting route sorted by ride time.
- `index.html`: time + AM/PM field block deleted; modal stat `mhArr` → `mhStopsN`.
- `css/styles.css`: `.freq-badge`, `@keyframes freqPulse`, `.bus-time .eta` deleted.

## Merges
- **Root cause of "Sec V" vs "Salt Lake Sector V"**: `Sec V` was simply never aliased.
- Stage 2 (`tools/2-geocode.js`) `GROUPS` is **last-write-wins** — a duplicated key silently
  kills the earlier entry. A duplicate `"Peerless": ["peerless"]` below
  `"Peerless Hospital"` was shipping the same hospital as two stops. All duplicate keys removed.
- `keyOf()` keeps spaces, so `p t s` ≠ `pts`; groups that only listed one form never fired.
  Added: PTS, SDF, CIT Road, City Centre 1/2, Dumdum Cantonment, Dumdum Chiria More,
  Acropolis Mall, Westin, Esplanade L20, Dhola, Nabadiganta, Shishumangal Hospital.
- **Merge rule that matters**: a pair appearing on the *same route* is never merged — that
  proves they are two stops. `Kakdwip` / `Kakdwip Bus Stand` co-occur on SD-11/19/50/82, so
  they stay apart. Same test protects `<village>` / `<village> Bazar`.
- Deliberate non-merges are documented in a comment at the end of `GROUPS`.

## Bug found: locality folding wiped routes
`buildIndexes()` in `js/app.js` did `ROUTES_BY_STOP.set(area, [])` and then skipped any route
that already served the area name. Because `Joka`, `Thakurpukur`, `New Town` and
`Salt Lake Sector V` are **both** localities and real stops, every route serving them by name
was erased from the index. `Joka → Esplanade` returned **2 of 24 buses**. Fixed by not
resetting the list and only adding routes that reach a *different* member.

## New: STOP_ALIASES
Merging removes old spellings from `BUS_STOPS`, so typing "Sec V" would return nothing.
Stage 2 now writes `tools/cache/alias-map.json` (every spelling a source used → canonical),
stage 3 folds it through the merge into `STOP_ALIASES` (979 keys, incl. punctuation-stripped
variants like `secv`), and `canonicalStop()` in `js/app.js` falls back to it and toasts
`"Sec V" is now Salt Lake Sector V`.

## Final numbers
537 routes · 1896 distinct stops (was 2009) · 481 plotted (25%, was 30%) · 228 merges ·
979 aliases. Coverage dropped because junk coordinates (a point 46 unrelated stops all claim)
are no longer promoted to "verified".

## Follow-up: the stop dropdown did not work on mobile

**Cause.** The two search fields were `<input list="stopList">` + `<datalist>`. iOS Safari and
several Android browsers either ignore `<datalist>` outright or open a native sheet that cannot be
filtered — so on a phone the field did nothing. There was no custom dropdown at all; the datalist
was the entire mechanism.

**Fix.** Replaced it with a combobox drawn in the DOM (`setupCombo` / `fillCombo` / `comboMatches`
in `js/app.js`, `.combo*` rules in `css/styles.css`, panel markup + ARIA in `index.html`).
`buildStopList()` and the `#stopList` element are gone.

Touch details that are load-bearing — do not "simplify" these away:
- Rows are **46px** tall; the list scrolls with `overscroll-behavior: contain`.
- Selection is on **`pointerdown` with `preventDefault()`**, because a tap blurs the field before
  `click` lands. A `click` handler stays as a fallback (no `panel.hidden` guard — choosing twice is
  harmless, doing nothing is the bug being fixed).
- The list **flips above** the field when space below is short, measured with `visualViewport`
  (only that shrinks with the keyboard; `innerHeight` does not).
- **No close-on-scroll.** The panel is anchored inside the field so it travels with it. Closing on
  scroll breaks the phone case, where focusing a field makes the browser scroll it above the
  keyboard. (I added this at first and it was wrong — caught by a screenshot taken after a scroll.)
- Inputs are **16px**; anything smaller makes iOS zoom the page on focus.
- Empty field → busiest 8 stops, so tapping visibly does something instead of looking broken.
- A merged-away spelling (`sec v`) gets its own row in the list, not just at search time.

**Also fixed:** the empty-state copy still promised buses "over the next 2 hours" — leftover from
the removed time window. Now reads "every bus that runs your stretch … across 537 real routes".

**Harness gotcha.** In headless Chromium `document.hasFocus()` is false, so `element.focus()` sets
`activeElement` but fires **no focus event**. Dispatch `new FocusEvent('focus')` explicitly to test
focus-driven UI.

**Verified:** panel opens on focus with 8 popular stops; `joka` → Joka / Joka Khalpole / IIM Joka;
`sec v` → alias row; `zzzzq` → "No matching stop"; tap fills the field and moves focus on; Arrow
keys + `aria-activedescendant`; Escape closes; flip works (panel 184–459 above wrap at 466–521);
row height 46px; input font 16px; quick-pick, deep link `?from=Sec%20V&to=Thakurpukur` and
`Joka → Esplanade` all still correct.


## Follow-up 2: mobile layout audit found two more real bugs

Re-verified the dropdown in a real headless browser and hit-tested every row with
`elementFromPoint` instead of just eyeballing a screenshot. Two genuine defects:

**1. The next field painted over the open list.** `.input-wrap:focus-within` lifts itself with
`transform: translateY(-1px)`, and a `transform` opens a stacking context. That trapped `.combo`'s
own `z-index: 70` *inside* the focused wrapper, so the destination field — later in the DOM,
`z-index: auto` — painted across the middle of the dropdown. On a 390px phone the list came out in
three stripes and the middle row was un-tappable (`elementFromPoint` returned `#destination`).
Fix: give the wrapper itself a `z-index` (`.input-wrap:focus-within, .input-wrap.has-combo.is-open
{ z-index: 5 }`) so the whole subtree, list included, stays above its siblings.
**Lesson: a `z-index` on an overlay is worthless if any ancestor between it and the shared stacking
context has a `transform`/`filter`/`backdrop-filter`. Lift the wrapper, not just the panel.**

**2. The header note was sliced off.** `.mini-note` is `white-space: nowrap` and measured **494px
inside a 346px card**; `body { overflow-x: hidden }` meant it was clipped mid-word with no scrollbar
to reveal it. Fix: `max-width: 100%`, plus `white-space: normal` below 520px so it wraps to two lines.
Note `document.scrollWidth > clientWidth` was **false** the whole time — overflow clipped by
`overflow-x: hidden` is invisible to that check. Measure the element against its container instead.

**3. Alias gap: declared spellings were not searchable.** `GROUPS` declared
`salt lake sector 5`, `saltlake sector v`, `p t s` and more, but stage 2 only recorded spellings it
*encountered* in the source lists. Those three appear in no published list, so they had no alias and
a search for them returned nothing (`rhTitle` never updated, empty state shown).
Fix in `tools/2-geocode.js`: after building `VARIANT`, walk `GROUPS` and record **every declared
variant** into `ALIAS_MAP`. The table is the statement that those spellings are the same stop, so all
of them should be findable. Added the spelled-out forms (`sector five`, `sec five`, `salt lake sector
five`) to the group too. Aliases 979 → 1125.

**Harness gotcha (new).** The submit handler defers `runSearch` by **240ms** via `setTimeout`, so a
`--setup` block that fires submits in a loop and reads the DOM synchronously captures all zeros. Chain
the pairs with `setTimeout` (≈650ms apart) and read `window.__x` in `--diag`, or the audit lies.

**Also:** `tools/audit/load.js`'s `findRoutes()` is a plain name match over the raw dataset — it does
**not** reproduce the app's locality folding or bidirectional segment matching. `Salt Lake Sector V ->
Thakurpukur` is 0 there and 4 in the app. Added a comment saying so; it briefly misled me.
